# 試験の見直し（利用者の困りごとから）

試験が通っても、利用者が困らないことの根拠にはなりません。この表では、各ファイルが利用者のどの困りごと（先へ進まない、絵が変わる、落ちる・固まる、崩れる、頼んだ通りに描かない）を見ているかと、間違った動きでも通ってしまうかを書いています。

## 仕組みの穴（ファイル 1 つではなく、全体で通ってしまう所）

1. 待つ所が時間切れでも黙って返っていました（test_chatdraw の wait_idle・wait_bg と、autosel・confirm・layerkeep・memory・redpen3 の待つ所）。固まっても後ろの確かめが偶然通れば緑でした。時間切れで落とすように直しました。
2. scripts/run_tests.py は、飛ばした試験を OK と数えていました。アプリが配る部品（scipy、scikit-image、numpy、PySide6、Pillow）が無くて飛ばした試験は落ちたとして数え、ほかの飛ばした試験は名前を出すようにしました。
3. tests/needs_models.txt の 24 ファイルは、torch の無い機械では丸ごと飛ばされます。Actions の atelier-e2e の回帰の段は決まった 7 ファイルしか流さないので、この 24 ファイル（赤ペン・レイヤー・ショートカットなど）はどこでも流れていません。torch を入れて全部を流す段を Actions に置くのは直していません（重い作業なので、置く場所の判断を返します）。
4. .claude/hooks/test.sh は何も流さずに exit 0 で終わります。「マージの前に test.sh を流す」決まりは、今は何も確かめていません。フックはユーザーが入れる物なので触っていません。

## 精度優先の試験（tests/test_phases.py）で直すべき点

手を入れていません。作り直す作業に渡す点です。

1. 偽の検品は、決めた回数（BAD_TIMES）のあと必ず通る形です。小さな模型の砂嵐の絵のように、検品がずっと通らない場合に先へ進むか・止める以外で固まらないかを見る試験がありません。サムネイルを描き続けた不具合は、この形の外で起きました。
2. 偽の模型（Painter）は、頼み・種によらず同じ絵を返します。同じ工程を描き直しても絵が同じなので、「同じ絵を描き続けている」ことを絵からは見分けられません。
3. test_stop_between_phases は Stopped が出たことだけを見ています。止めた所までの絵と、どの工程まで進んだかを見ていません。
4. test_pause の再開の確かめ（`len(history) >= done_before + 残りの工程`）は下限だけで、再開のあと同じ工程を何回描いても通ります（test_pause は精度優先の作り直しに合わせて直すため、今回は触っていません）。
5. PreviewTest の上限（total * 2 + THUMBS）は、total が増え続けると一緒に緩みます。
6. WindowFlowTest は check_ai・_keep_original・検品の全部を mock で置き換えており、窓が本物の検品を呼ぶ経路は見ていません。
7. test_director の RealModelTest（本物の小さな模型）は「描く」の tries が 1 以上で通り、出た絵の中身を見ていません。
