# 人物以外の題材の検品

AtelIer の検品（`atelier/qc`）と精度優先の工程は、人物の形（手・足・顔・骨組み）を前提に作ってきた。建物・風景・乗り物・物・文字の絵では、
人が一目で気づく崩れ（倒れた縦の線、塗っていない空と地面の間、車輪の数、読めない文字）を測っていなかった。
ここでは題材ごとに何を見て何を見ていないかを表にし、足した検品と、表に無い題材をその場で調べて検品する形を書く。
表の中身は `atelier/qc/subject_check.py` の `COVERAGE` と `TOOLS` と同じで、`tests/test_subject_check.py` が全部の題材の行があるかを見る。

## 検品の棚卸し

「この検品」と書いた物が `subject_check.py` で足した物。

| 題材 | 見ている物（部品） | 見ていない物 |
|---|---|---|
| 人物 | 人数（RT-DETR・タグ）、頼んだ物（wd-tagger）、手の指の数（hand_check）、足・顔（hand_check）、骨の比（VitPose）、余分な部位（segformer の塊）、反転・縮めて見る、地平線の傾き | 持ち物の数と持ち方、服の左右 |
| 動物 | 頼んだ物（wd-tagger）、顔・足の有無（subject_kind の face）、足の数の崩れ（タグ、この検品）、地平線の傾き | 足の本数を画素で数える、尾・耳の数 |
| 乗り物 | タイヤの丸み・左右のタイヤの大きさ（phase_tools）、左右対称（正面の頼み）、遠近の収束、車輪の数（数の決まった乗り物、この検品） | 車の向きごとの見える車輪の数、窓・扉の数 |
| 文字とロゴ | 頼んだ文字が読めるか（OCR があるとき、この検品） | 字の形の崩れ（OCR が無いとき）、ロゴの左右対称 |
| 模様 | 繰り返しのそろい（この検品） | 継ぎ目（端と端がつながるか） |
| 建物と街 | 地平線の傾き、遠近の収束（2 本）、縦の線の倒れ（この検品）、窓の並び（この検品）、消える点のそろい（この検品） | 窓の大きさのそろい、階の数 |
| 室内 | 地平線の傾き、遠近の収束、縦の線の倒れ（この検品）、消える点のそろい（この検品） | 家具の脚の数、床と壁の境目 |
| 物 | 頼んだ物（wd-tagger）、画面の重さ、頼んだ数と塊の数（この検品）、その場で調べた項目（research_check） | 部品の並び（その場で調べた項目のうち order は測る道具が無い） |
| 風景 | 地平線の傾き、水の光・葉のつや、空と地面の間の塗り残し（この検品）、空が下の逆さの絵（この検品） | 山の稜線の重なり、影の向きのそろい |
| 背景だけの絵 | 頼んでいない人（wd-tagger、この検品）、地平線の傾き、遠近の収束 | 主役が無いことの確かめ |

## 描く道具の棚卸し

| 描く道具 | 人物以外での動き |
|---|---|
| 部品分け（segformer の顔・腕・脚） | 人物だけ。人物以外は塊が出ず、直しの囲みが作れない → subject_parts の空・地面・主役の面で補う |
| 囲み（hand/foot/face の枠） | 人物だけ。乗り物はタイヤの枠、遠近は線の枠（phase_tools）。建物の縦線・窓は線の枠（この検品の box） |
| 下塗りの面（主役のシルエット） | どの題材でも動く（明るさのシルエット）。全画面の風景は主役が無く、空と地面の面に分ける（subject_parts） |
| 工程: 目的・サムネイル | どの題材でも動く（頼み・画面の重さ） |
| 工程: アタリ | 人物前提（骨組み・等身）。物（object）は頼んだ物と画面の重さだけ。建物の遠近の線、風景の空と地面の段は STEPS で持つ |
| 工程: 線画・塗り・仕上げ | 線・塗りは題材を問わず動く。仕上げの手・足・顔は顔のある物だけ。物は縮めて見る・タイヤ・対称・遠近 |

## 足した検品の測り方

| 題材 | 崩れ | 測り方 | 閾値（私の推測） |
|---|---|---|---|
| 建物と街・室内 | 縦の線の倒れ | 強い縁のうち縦に近い画素の向きの中央値（ぼかしてから Sobel）。見上げ・見下ろしの頼みでは見ない | 4 度 |
| 建物と街・室内 | 消える点のそろい | 斜めの線（Hough）どうしの交点が、交点の中央値から対角の 15% 以内に入る割合 | 0.4 |
| 建物と街 | 窓の並び | 暗い小さな塊（窓）を段に分け、段ごとの間隔の変動係数の一番大きい物 | 0.35 |
| 風景・背景だけの絵 | 空と地面の間の塗り残し / 逆さ | 白く平らな行が続く帯の高さ / 下の 3 分の 1 が上より青く明るい | 帯 2% |
| 乗り物 | 車輪の数 | phase_tools のタイヤの塊の数。自転車・バイク・一輪車・三輪車だけ（車は向きで見える数が変わる） | 決まった数 |
| 動物 | 足の数 | wd-tagger の extra legs・multiple legs・missing limb など | タグごとの下限 |
| 物・動物・乗り物 | 頼んだ数 | 頼みの数の語（three、3、三つ）と、シルエットの塊の数 | 一致 |
| 文字とロゴ | 読めるか | 頼みの引用符の中の文字と、OCR（rapidocr_onnxruntime か pytesseract）の読みの近さ | 0.8 |
| 模様 | 繰り返しのそろい | 明るさの自己相関で周期を読み、隣の周期の区画との明るさの差 | 0.18 |
| 背景だけの絵 | 頼んでいない人 | wd-tagger の 1girl・solo など | 0.4 |

測れなかった物（線が無い、OCR の部品が無い、タグが読めない）は `unreadable` に理由を残し、「崩れが無い」とは返さない。
精度優先へのつなぎは、アタリ（人物以外）と仕上げ（顔の無い物）で `subject_check.phase_flaws` を呼び、崩れの文を工程の確かめに渡すだけにした。
崩れの文は `phase_items.KEYWORDS` の新しい項目（建物の縦線、窓の並び、空と地面、車輪の数、物の数、文字、模様、調べた項目）に振り分ける。
`unreadable` は今は工程の崩れにしていない。工程の数に上限が無いので、部品が無いだけで描き直しが終わらなくなるのを避けた（決めるのは利用者）。

## 足した部品とライセンス

| 部品 | 使い方 | ライセンス・メンテナンス |
|---|---|---|
| numpy・scipy（既にある） | 縁・塊・自己相関 | BSD-3。どちらも活発に保守されている |
| wd-vit-tagger-v3（既にある） | 足の数・人のタグ | Apache-2.0 |
| rapidocr_onnxruntime（任意） | 文字の読み | Apache-2.0。RapidAI が PyPI に出し続けている。入っていなければ文字は読めないと返す |
| pytesseract（任意） | 文字の読み（rapidocr が無いとき） | Apache-2.0。tesseract の本体が要る |

rapidocr と pytesseract のライセンスと保守は、この文を書いた時点の知識で、PyPI の頁をこのセッションで開いて確かめてはいない。

## その場で調べて検品する形

題材が表に無い（`subject_check.kind` が `unknown`）とき、`research_check.check` が次の順で進める。

1. 覚えた項目があれば、調べずに使う（利用者の置き場の `qc/subject_checks.json`）
2. 無ければ思考の模型（`atelier.ai.thinker.research(subject, ask_web=, fetch=)`）が、確かめる項目を調べる。まず言葉の模型の知識、
   足りなければ `ask_web(subject)` で利用者にその場で外へ取りに行く許しを聞き、許されたときだけ `fetch(subject)` で説明を取る
3. 項目は `{"name", "kind": count|shape|ratio|order, "expect"}` の決まった形で受け、形に合わない物は捨てる
4. 数は名前の語（車輪・窓・本体など）から測る道具を選んで数え、比（幅・縦横）は主役のシルエットの幅と高さで測る。形と並びは、
   測る道具がまだ無いので `unreadable` に残す
5. 項目だけを題材ごとに覚える。絵・描く言葉・絵の方向を寄せる重みは覚えない

思考の模型の部品が無い版（`thinker.py` がまだ main に無い）では、項目は空になり、`unreadable` に理由が残る。

## 人物以外の面分けと工程の段

`atelier/ai/subject_parts.py` は、模型を使わずに空・地面・主役の 3 つの面を取る（`regions`）。人物の部品分けが面を返さない絵で、
直しの囲みと下塗りの面に使う。`STEPS` は題材ごとに工程（アタリ・線画・下塗り・仕上げ）で足す確かめの段を持つ。工程の表（phases.PHASES）は変えていない。

## 確かめ

合成の図形（傾けた建物、窓のずれ、白い帯の風景、逆さの風景、崩れた縞）での数字は `tests/test_subject_check.py` に入れた。

| 測る物 | 崩れていない絵 | 崩れた絵 |
|---|---|---|
| 縦の線の倒れ（度） | 0.0 | 8.9（9 度傾けた絵）、2.9（3 度） |
| 模様の差 | 0.0 | 0.292 |
| 窓の間隔の変動 | 0.008 | ずらした窓で大きくなる |

模型で描いた絵での確かめは Actions の `subject-qc.yml`（題材ごとに頼み 2 つ、cagliostrolab/animagine-xl-4.0、私の推測で選んだ模型）で流す。
